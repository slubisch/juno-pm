## 01 Context · Data Requirements

**Required sources, and exclusions**

Customer workspace
Juno provides a webpage with four views:
- Customers: Lists customer profiles and offers an Add customer action.
- Import: Accepts files or pasted content and shows a synthesis preview before anything is saved.
- Backlog: Shows feature requests ranked by RICE or revenue score, including customer reach.
- Report: Summarizes financial impact across customers and features.
A customer profile requires customer name, ARR, renewal date, and features. Profiles may also show segment, risk, summary, and related Jira issue IDs.
Sources and exclusions
Juno analyzes user-provided content associated with one selected customer per run. V1 sources include:
- Files: .pptx, .xlsx, .xls, .csv, .docx, .txt, .md, .json, .pdf, and .vtt
- Pasted content: Webex transcripts, Jira exports, Airtable exports, internal notes, and Microsoft OneNote notes
OneNote content is provided by paste or by uploading an exported file; V1 does not connect to OneNote directly. PDF was named in the initial sketch but does not appear in the sample Import format list, so V1 support for PDF needs confirmation.
Excluded: Automatic data discovery; live retrieval from Webex, Jira, Airtable, or OneNote; sources not provided or selected for the customer; and information belonging to other customers. Juno must not combine customer data.
For ARR, renewal date, and risk, XLS is authoritative when sources conflict. Juno shows the discrepancy and proposed value for review. For other imported information, the user chooses whether it updates an existing field or is added as supporting evidence.

**How fresh must it be**

Files and pasted text are snapshots from the time they are provided. Juno does not continuously monitor sources.
A synthesis creates proposed customer, Backlog, and Report changes. These remain under review and do not affect saved records or aggregate views until the user approves them. If a source cannot be read, Juno names it and marks the synthesis incomplete rather than silently omitting it.

## 02 Tools · System Capabilities

**The verb list**

V1 verb list
- list_customers() — READ
- read_customer(customer_id) — READ
- read_import(customer_id, source_id) — READ
- analyze_customer(customer_id, source_ids) — DRAFT
- propose_customer_changes(customer_id, changes, evidence) — DRAFT
- propose_backlog_changes(customer_id, changes, evidence) — DRAFT
- propose_report_changes(customer_id, changes, evidence) — DRAFT
- create_customer(name, arr, renewal_date, features) — WRITE
- store_import(customer_id, file_or_text) — WRITE
- approve_changes(change_set_id) — WRITE
- reject_changes(change_set_id, reason) — WRITE
Approval applies the selected changes. The design leaves room for future read-only source access through a tool such as fetch_source(source, customer_id, scope), but that capability is not available in V1.

**Deliberate omissions**

No unapproved changes to customer records, Backlog, or Report; no live pulls in V1; no automatic resolution of conflicts; and no customer messaging.

## 03 Loop · AI Costs & Latency

**Turn ceiling and escalation**

Run model: One run analyzes one customer and returns one synthesis with proposed changes for review.
Completion: If Juno cannot read a source or complete the analysis, it identifies the affected source, explains the limitation, and labels the synthesis incomplete. It must not silently omit source material. The numeric internal retry limit will be set during implementation and validated against representative inputs.
Escalation: For ARR, renewal date, and risk conflicts, Juno proposes the XLS value with evidence. For other unresolved conflicts, it presents the competing values and sources for the user to decide.

**Latency and cost target**

Latency: Measure time from Analyze to a reviewable synthesis. Set a numeric target after validating representative input sizes and formats.
Cost: Track financial operating cost in dollars per customer analysis; token usage is a diagnostic measure. Set a dollar ceiling before launch, based on expected usage and the approved budget.

## 04 Memory · Data Requirements

**What persists, at what scope**

Juno retains original uploaded files with their customer records so users can revisit the evidence during iteration. Users can remove files. The retention period must be set by the organization.
Juno also retains the customer record, synthesis versions, proposed changes, and user decisions needed to continue work on that customer.

**Expiry and write rules**

Store uploaded files and derived customer analyses according to the applicable Cisco retention schedule and data-protection requirements. Before launch, the service or data owner must determine the applicable record category and configure retention and destruction accordingly. User removal is subject to retention requirements and any applicable holds

## 05 Permissions · AI Risks & Mitigations

**The permission tier**

| Side-effect class | Tier |
|---|---|
| read | auto |
| draft | auto |
| write | confirm |
| send | blocked |

**Justification**

Read — auto: Juno reads only the customer and sources selected for the run. V1 does not pull from connected systems.
Draft — auto: Juno can prepare summaries and proposed changes because drafts do not alter saved records.
Write — confirm: Saving files or customer records changes persistent workspace data. Juno must show the proposed changes and receive user approval before applying them.
Send — blocked: Customer-facing messages and external publishing are outside V1. They carry external and reputational effects beyond the workspace.

## 06 Verification · AI Testing & Measurement

**The check before output ships**

For important profile details and feature claims, Juno shows the source and relevant location—for example, the filename plus sheet and row, or document and page.
Juno identifies conflicting, missing, or unreadable evidence. It distinguishes sourced facts from interpretation and does not silently resolve conflicts beyond the stated XLS authority for ARR, renewal date, and risk. The user reviews proposed changes before they affect saved customer data, the Backlog, or the Report.
